# FKP Routine System 0.6.2

A native Windows application for Payment Online, Performance Daily, Customer Documents, Enforcement and Performance Success Rate. The owner-provided robot icon is used by the executable, window and project shortcut.

## Workflow contracts

Payment Online retains the legacy source headers, employee/type/election/forecast mapping and Query2 rules. It uses the owner-selected \\10.0.0.97\kuma$\X\FKP Payment Online Round.mdb. Each job imports into a private working copy, never the original MDB. Round 1 produces the report without Action writes; rounds 2–12 prepare the existing Action queries. Action destinations remain the actual linked databases, with separate transactions/preimages/readback per connection. A partial commit is retained and never automatically replayed. Working MDBs containing saved connections are retained only as Windows-user-encrypted recovery files. Payment opens on Table1; the Query1 worksheet remains in the workbook with its data intact and is hidden. Excel/ZIP attachment names use the source report name without _processed.

Performance invokes Daily only. Stages 01–05 are retained in Performance/Process; only stage 02 is attached to email and stage 05 is read back and compared before import to dbo_PFM_DAILY. The saved metadata is formatted as literal text to prevent Excel converting OCT-26/ISO dates to serial dates. Financial/filter/rank rules are unchanged. The configured owner database \\10.0.0.97\kuma$\X\FKP Performance.accdb resolves its existing dbo_PFM_DAILY link; connectivity and all 11 fields were verified read-only for 0.6.1.

All five workflows share flexible classification from Body filenames, attachment names and Subject filenames, then exact/approximate work words in Subject/Body. Customer Documents accepts A10xx/A10xxL placeholders mapped to office 15, names without extensions, and optional transport-date/duplicate-office prefixes. A wrong subject date does not override an explicit document filename. Multiple files in a mail are independent work units. Extracted subfolders are preserved in the password ZIP sent to the original Document/CC Data recipients.

Enforcement accepts decorated/near titles and Body/image references for A1015/A1015L Approval or Reject files, including BAY and numbered variants. It accepts a decrypted PDF directly or a ZIP/RAR of PDFs. Multiple files named in the same mail form one batch and wait until every source is available. Content hashes prevent repeating any previously processed input.

Enforcement OCR captures tables only at 400 DPI. Table headings and blank cells are retained; clipped row fragments are joined across page boundaries. The supplied Approval, Approval BAY and Reject layouts have 21, 20 and 18 columns. Excel contains table worksheets only, with no unrelated mail text, signatures, full-page text or audit sheets. Version 0.6.2 appends one final column, วันที่อีเมลใน PDF, using the visible upper-right Outlook date/time in the PDF (for example พ. 28/10/2026 17:53). The weekday follows the printed date; no filename, filesystem or outer email date is substituted. Continued rows use their own PDF header date. A missing/ambiguous header remains blank and is logged. Native Tesseract TXT output preserves Thai spacing and combining marks; TSV is used only for confidence. Colored header masks, aspect-ratio retries, field-specific digit recognition and green-corner removal improve cell recognition without a spelling dictionary that changes names or figures. Page/cell evidence remains internal in Process for review.

As requested by the owner, Enforcement proceeds automatically after successful OCR without manual cell review. It builds a password-protected ZIP containing all original PDFs under PDF/ plus the table-only Excel, without generated Input_1/Input_2 folders. Duplicate relative PDF filenames receive a numeric suffix so neither file is lost., resolves Enforcement-specific To/CC and sends or opens Draft according to saved mail settings. The original PDF bytes and the ZIP are verified before delivery and outcome state is durable. An OCR failure cannot trigger an email; an uncertain/completed delivery is never automatically repeated. Draft does not archive sources. Enforcement does not write a database. When GPG produces a password-protected ZIP, the extractor uses the current user's saved ZIP password and supports ZipCrypto/AES input. Missing/wrong passwords stop before OCR with an extraction-specific error. A failed pre-mail/pre-review job from before this fix may be attempted once by the updated processor; pending/unknown/sent/draft outcomes and jobs already prepared for delivery are never automatically retried. Previous attempt evidence is retained. Jobs created by earlier releases keep their previous delivery state and are never automatically resent.


Performance Success Rate is separate from Performance Daily. It reads Body filenames such as A10XX_Performance_SAM_OA_Oct26.zip.gpg, maps XX to office 15, and accepts A1015/A1015L with optional transport-date prefixes. The source folder is \\10.0.0.243\pgp-data$. Received date distinguishes repeated monthly deliveries. After PGP decryption, ZIP or RAR content is detected and extracted, preserving nested names and all file bytes, then repacked into an AES-256 password ZIP in a separate Delivery folder so the outgoing ZIP never collides with the decrypted input ZIP. Its own To/CC fields start blank; the new task starts disabled until configured and selected. It performs no OCR, Daily stages or database writes. Corrupt, ambiguous, encrypted-inner or multipart RAR inputs stop before mail.

The main Status panel shows actual scan events, last successful scan time, matching mail count, mailbox/folder, next poll countdown and bounded live logs. Unknown counts remain blank until a scan finishes. Send From alone follows FKP Frequency: an editable SMTP selector with an explicit เลือกบัญชี action; asynchronous refresh preserves typed text. Sending requires exactly one matching Outlook account and readback. Draft display/save must retain that account.

## Deployment and rights

Program/ contains one current portable release; Development/ contains source, templates, public defaults and tests; Archive/ contains preserved releases and isolated verification.

Operational logs and work files are under \\10.0.0.97\Z Log Bot\FKP Routine System Log, separated into Payment Online, Performance, Customer Documents and Enforcement, each with Logs and Process. Completed files are under the matching task in \\10.0.0.97\Z Collect Bot\FKP Routine System. D:\KUMA BOT is not used.

The release bundles GPG, the separately redistributable UnRAR component, Tesseract Thai/English models and its Python runtime. It runs as the current Windows user, without an elevation manifest. Settings are saved in that user's LOCALAPPDATA/FKP_Routine_System. Passwords are protected with Windows DPAPI and are not shipped in public defaults. PGP decryption reuses existing local saved settings automatically. An empty optional passphrase does not override the machine key store/agent with an empty password; an empty key-folder setting uses the GnuPG default used on that machine. Private GPG keys are never bundled; each execution user must have an authorized GPG key folder and access to the configured shares, Outlook mailbox/sending account, Office/DAO components and linked SQL databases. Managed GPG/OCR paths saved from older releases follow the running release; custom tool paths and private key folders remain unchanged. No Windows/share ACL, Office trust policy or global registry setting is changed.

Flexible triggers examine both read and unread mail within the configured lookback and per-folder limit; durable mail/file hashes prevent replay. The GUI exposes both limits in General settings and preserves an older profile's saved limits. The default remains 24 hours / 200 items. Office/date/round identities remain exact, Recall notices and Adjust are excluded, and ambiguous metadata is reported without processing. Files already in 03 Check are reported and never automatically taken from the archive. A workflow whose dependencies or recipients are missing no longer prevents other ready selected workflows from polling. Old Daily mail cannot select a new transport file by monthly name; a cutoff mismatch does not reserve that file against the correct mail.

OCR language checks and OCR processing use CREATE_NO_WINDOW plus hidden startup settings; the application no longer invokes the visible version/language subprocesses of pytesseract. GPG and UnRAR also remain windowless. Opening the GUI is idle. Saving, checking readiness or reviewing output does not send email. Start or the explicit --once/--monitor flags activate only selected tasks. Shared task locks and a durable per-task ledger prevent concurrent replay across machines. Missing files remain pending; uncertain mail/SQL results require investigation rather than automatic retry.

Legacy mail/rules are migrated into public defaults. On a user's first run, an existing local legacy config may seed its secrets; subsequent execution is independent of that D: path. A clean machine configures its own protected profile. Different Outlook Inbox display languages are handled through the provider's default Inbox.

## Developer verification

Run python -m unittest discover -s tests -v in Development. The --verify-source, --verify-payment and --verify-enforcement flags require a new --verification-root and never send email, commit production SQL or archive production inputs. Native UI verification uses isolated profiles and never presses Start.

Verified evidence includes the original Daily 1,204-row run, a real Payment 10-row report with Action selections read-only, portable GPG decryption, and table-only Enforcement PDF OCR fixtures. Version 0.6.2 passes 99 isolated tests covering automatic Enforcement delivery, real RAR4/RAR5 extraction, password reZIP, Body matching, sender verification and profile upgrades. Transaction/send faults, multiple Body files, profile encryption and blank/last-column completeness are covered by tests. Production mail delivery/SQL writes and execution on another physical machine have not been tested.

The local Git repository records the verified source under the owner-selected author name FKP_Routine_System. Email is intentionally empty because no address was supplied. Identity settings apply only to this repository. The exact source commit is recorded in release build.json and the delivery receipt; no remote is configured.
